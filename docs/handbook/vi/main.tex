\section*{Executive Report}
\addcontentsline{toc}{section}{Executive Report}
Repository nay thuc thi mot he thong sentiment analysis co hai mat ro rang: online inference plane va offline ML lifecycle plane. Mat online gom Angular frontend, Nginx reverse proxy, FastAPI backend, va mot model orchestration layer chay trong cung process de phuc vu predict, aspect extraction, sarcasm detection, SHAP explainability, health, metrics, va batch CSV dong bo. Mat offline gom DVC pipeline cho download du lieu, tien xu ly, validation, finetuning, evaluation, ONNX export, benchmark, va MLflow tracking.

Điểm mạnh lớn nhất là tính end-to-end có thật ở cấp repository, abstraction hợp lý thông qua \texttt{contracts/model\_interface.py}, monitoring có mặt, va đường đi từ training đến serving bằng artifact ONNX. Điểm yếu lớn nhất là control plane: không có authentication, không có authorization, batch status la mock, evaluation status nam trong memory, và các path nặng vẫn cùng chia sẻ một process.

Hệ thống phù hợp nhất với nhận diện \textbf{Hybrid Architecture: modular monolith runtime ket hop workflow ML platform}. Đây không phải hệ thống microservice phân tán. Backend la mot deployable FastAPI service sở hữu routing, validation, và orchestration model. Xung quanh nó là frontend container, monitoring services, và bộ script/pipeline ML cùng sống trong một repository.

\subsection{Startup Sequence}
Startup flow bắt đầu từ container entrypoint, đi qua FastAPI lifespan hook, rồi tạo \texttt{BaselineModelInference} và nạp model artifacts. Nếu artifact, tokenizer, hoặc backend mode không khớp, service không đi vào trạng thái ready.

\subsection{Prediction Sequence}
Prediction sequence là luồng đồng bộ chính: request đi từ frontend qua backend, qua language detection, model inference, rồi trả \texttt{PredictResponse}. Đây là path có tần suất cao nhất và quyết định độ trễ cảm nhận của người dùng.

\subsection{Batch Sequence}
Batch sequence đọc CSV, xử lý từng dòng theo chunk, rồi trả kết quả đồng bộ thay vì job queue thật. Điều này đơn giản hóa triển khai nhưng giới hạn throughput và làm giảm khả năng retry / recovery.

\subsection{Evaluation Sequence}
Evaluation sequence chạy như background task trong cùng process, ghi trạng thái vào memory và đẩy metric / report ra file hoặc MLflow. Cách này đủ cho pilot, nhưng chưa phù hợp nếu cần durability hay tracing đầy đủ.

\section{Section 6 - Backend Analysis}
\subsection{FastAPI Architecture}
Backend la mot FastAPI application don le trong \texttt{src/main.py}. No su dung:
\subsection{Routing and Dependency Injection}
Routing tập trung trong một file chính, với dependency injection được dùng để lấy model instance, validate request context, và gắn các route handlers vào cùng lifecycle. Điều này làm hệ thống dễ hiểu nhưng tạo một điểm tập trung lớn.

Application scalability bị giới hạn bởi một FastAPI process sở hữu cả API lại model orchestration. Khi concurrency tăng, contention sẽ xuất hiện trước tiên ở CPU, rồi đến event loop và memory pressure.

\subsection{Model Scalability}
Model scalability bị chi phối bởi sentiment inference cộng thêm ABSA và SHAP. Nếu workload nghiêng về explain hoặc batch lớn, chi phí per request tăng đáng kể ngay cả khi ONNX đã giảm thời gian forward pass.

\subsection{Operational Scalability}
Operational scalability bị giới hạn bởi thiếu auth, thiếu alert routing, và batch/evaluation state không bền. Tức là mở rộng team hay traffic đều làm tăng risk vận hành nếu control plane không đổi.

\subsection{Primary Bottlenecks}
Nút thắt đầu tiên là SHAP/explain. Nút thắt thứ hai là batch inference đồng bộ. Nút thắt dài hạn là single-process ownership của backend cho cả serving và heavy ML workflow.

\subsection{Scalability View}
\begin{itemize}[leftmargin=1.2em]
  \item application scalability bi gioi han boi mot in-process model owner va khong co external queue
  \item model scalability bi gioi han boi chi phi ABSA va SHAP, khong chi sentiment inference
  \item infrastructure scalability bi gioi han trong khuon kho Compose hon la managed orchestration
  \item operational scalability bi gioi han boi access control yeu va workflow state khong ben
  \item data scalability tam du cho kieu CSV va DVC hien tai, nhung governance van thu cong
  \item team scalability bi anh huong boi kien thuc tap trung vao \texttt{src/model/}, \texttt{src/scripts/}, va deployment config
\end{itemize}

\section{Section 20 - Final Technical Conclusion}
\subsection{Major Strengths}
\begin{itemize}[leftmargin=1.2em]
  \item full repository-level ML lifecycle được implement thật
  \item runtime và training concerns được tách đủ rõ cho đội nhỏ
  \item contracts, tests, monitoring, và export paths giúp system audit được
  \item ONNX serving path, batch optimization, va MLflow integration la nhung quyet dinh thuc dung
\end{itemize}

\subsection{Major Weaknesses}
\begin{itemize}[leftmargin=1.2em]
  \item không có authentication hay authorization
  \item batch async semantics bị mock, evaluation state không bền
  \item frontend/backend contract drift quanh language handling va batch behavior
  \item heavy inference features chia sẻ cùng một public process, không có workload isolation
\end{itemize}

\subsection{Critical Risks}
\begin{itemize}[leftmargin=1.2em]
  \item su dung trai phep cac endpoints dat tien hoac co tinh chat quan tri
  \item vận hành hiểu sai do batch status không phản ánh thực tế
  \item performance sup do khi traffic nghieng ve explain hoac batch
  \item artifact va secret handling yeu trong build va deployment
\end{itemize}

\subsection{Production Readiness and Final Verdict}
Chỉ dựa trên bằng chứng implementation, hệ thống \textbf{chưa sẵn sàng cho production enterprise}. Tuy vậy, đây là một Advanced MVP đáng tin và là một nền tảng demo hoặc pilot kiểm soát tốt. Kiến trúc chạy được end-to-end, ML lifecycle có thật, và repository có giá trị kỹ thuật rõ ràng. Khoảng cách hiện tại không nằm ở chỗ thiếu feature; nó nằm ở chỗ thiếu control plane cần thiết để vận hành các feature đó một cách an toàn, bền vững, và mở rộng được.
